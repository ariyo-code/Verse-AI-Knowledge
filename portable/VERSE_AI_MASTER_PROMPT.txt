3. VERSE FAILURE / EFFECT RULES
======================================================================

Verse has failable expressions and effect specifiers.

Important rule:
If an operation is failable, use it in a valid failure context such as:

    if (Value := FailableExpression[]):
        ...

or another correct Verse failure context.

Known example:

    if (FortCharacter := Agent.GetFortCharacter[]):
        ...

Do not turn a failable call into ordinary non-failable syntax.

Known high-confidence signature from repository knowledge:

    (InAgent:agent).GetFortCharacter<public><native>()<transacts><decides>:fort_character

Meaning:
- it is failable;
- it uses `<decides>`;
- it returns `fort_character` when successful.

Effects matter.
Do not randomly add `<suspends>`, `<decides>`, `<transacts>`, etc.

4. CREATIVE DEVICE LIFECYCLE
======================================================================

Typical root:

    my_device := class(creative_device):

        OnBegin<override>()<suspends>:void=
            ...

Known lifecycle:
- `creative_device` has `OnBegin`;
- `creative_device` has `OnEnd`;
- do not rely on coroutines started from `OnEnd` completing.

Prefer:
- subscribe in initialization;
- store `cancelable` subscriptions when dynamic cleanup is needed;
- cancel them during logical teardown;
- clean per-player state on player removal when relevant.

Do not create duplicate event subscriptions each time an UI is reopened unless they are canceled or intentionally short-lived.

======================================================================
5. EVENT HANDLING PATTERN
======================================================================

Preferred pattern:

    OnBegin<override>()<suspends>:void=
        SomeDevice.SomeEvent.Subscribe(OnSomeEvent)

    OnSomeEvent(Agent:agent):void=
        ...

When extra context must be captured, use a small handler class instead of global mutable hacks.

Example architecture:

    action_handler := class:
        System : my_system
        TargetId : int

        OnTriggered(Agent:agent):void=
            System.HandleAction(Agent, TargetId)

Keep handler objects alive as long as the subscription needs them.

8. ASYNC / CONCURRENCY
======================================================================

Known Verse concurrency concepts:
- `sync`
- `race`
- `rush`
- `branch`
- `spawn`

Use `spawn` carefully.
Uncontrolled spawn calls can create duplicate long-lived tasks.

Good use case:
- launch a suspending routine from a non-suspending event callback.

Example:

    OnTriggered(Agent:agent):void=
        spawn{RunAsync(Agent)}

For short-lived UI tracking:

    TrackButton(Btn:button_loud)<suspends>:void=
        race:
            block:
                Btn.OnClick().Await()
                HandleClick()
            block:
                UIClosedEvent.Await()

Prefer events/listenables over polling.
