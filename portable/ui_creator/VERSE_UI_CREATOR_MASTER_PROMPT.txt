======================================================================
7. PER-PLAYER UI STATE
======================================================================

Each player should have independent UI state.

Typical architecture:

    ui_session := class:
        Agent : agent
        Canvas : canvas
        var Page : int = 0
        var SelectedIndex : int = -1
        CloseEvent : event() = event(){}

System:

    var Sessions : [agent]ui_session = map{}

The exact implementation must use valid Verse syntax/APIs.

When opening:
- close/replace an existing session if needed;
- build the new view;
- store the session;
- subscribe/await events safely.

When closing:
- remove widget;
- signal session close;
- clear state;
- avoid leaving orphan async tasks.

======================================================================
8. PLAYER UI ACCESS
======================================================================

Known pattern:

    if (Player := player[Agent], PlayerUI := GetPlayerUI[Player]):
        ...

Typical display:

    PlayerUI.AddWidget(MyCanvas)

Interactive UI may use a player_ui_slot with input mode when appropriate.

Typical removal:

    PlayerUI.RemoveWidget(MyCanvas)

Do not assume UI access can never fail.

======================================================================
9. RESPONSIVE LAYOUT
======================================================================

Prefer:
- anchors;
- alignment;
- SizeToContent when appropriate;
- relative positioning;
- clear parent/child layout.

Avoid designing every element using arbitrary absolute coordinates.

When reproducing a screenshot:
- first identify main zones;
- establish root anchors;
- create containers;
- then position children.

For centered modal-style UI:
- anchor to center;
- align around center;
- keep internal layout relative.

For HUD:
- anchor to screen edge/corner;
- avoid giant fixed margins when a relative anchor works.

======================================================================
11. BUTTON EVENT DESIGN
======================================================================

Do not create uncontrolled listener loops.

For static UI:
- subscribe once when possible.

For temporary/dynamic UI:
- use a session lifecycle;
- or race between click events and a close event.

Example architecture:

    TrackButton(Btn:button_loud, Session:ui_session)<suspends>:void=
        race:
            block:
                Message := Btn.OnClick().Await()
                HandleAction(Message.Player)
            block:
                Session.CloseEvent.Await()

The exact signature of widget events must be verified before use.

======================================================================
12. PAGINATION
======================================================================

For lists larger than the visible UI:

State:
- Page
- PageSize
- SelectedIndex

Derived:

    StartIndex = Page * PageSize

Display:
- slice/iterate visible entries safely;
- disable or hide invalid previous/next actions;
- clamp page after data changes.

Never assume data length stays constant while the UI is open.

Useful for:
- staff player list;
- garage;
- inventory;
- shop;
- leaderboard;
- whitelist list;
- logs.
